# Survey: packages/cli/src/enterprise (`plur-enterprise init`, epic 1797)

Survey by the Installer modelling agent, 2026-10-18, on branch formal/epic-1797. Leads, not findings. Paths are relative to packages/cli/src/enterprise/. Ranked by (risk × likelihood) / size. The orchestrator (`init.ts`, plan C task 10b) does not exist yet: `enterprise.ts` only parses arguments. Nothing in `packages/cli/src` imports cleanup, hello or summary so far.

1. **Header file tri-state (S)**: cleanup.ts:103-134, called at 80-85. Claim at 32-33: "removed only when no editor config still has a legacy entry or names the file, and every editor config could be read". Suspicion: line 115 `if (!existsSync(c.path)) continue`. existsSync returns false for any failed stat, including EACCES on a parent folder, so "could not look" counts as "not there". Risk: the header is deleted while an unproven editor still reads it, and that editor loses PLUR. Tests: enterprise-cleanup.test.ts covers unparsable and unproven configs, not ones that cannot be looked at.
2. **Backup before write (S)**: cleanup.ts:63-69 (run), 155-331 (per tool), 360-403 (backupWriter). Claims at 61-62 ("A write happens only after its backup succeeded") and 352-358. Suspicion: line 393 makes one `writeSync(fd, data)` call and ignores the returned byte count, and the backup is not fsynced. A short write is then accepted, and the config is changed with a truncated backup. Tests: enterprise-cleanup.test.ts (38).
3. **Backups never overwrite (S)**: cleanup.ts:381-384. The numbering loop runs first, then `'wx'` (O_EXCL). Looks sound.
4. **Owner-only (S)**: owner-only.ts:60-76, cleanup.ts:364-376 and 405-428. The claim at 352-358 is that a secret is never readable by anyone else. Sound by reading: protection is checked before writeSync, and the empty file is unlinked on failure. The Windows icacls output format has not been verified (mocked exec only).
5. **Hello exit paths (M)**: hello.ts:64-203, mcp-stdio.ts:23-45 and 126-148. Claims: mcp-stdio.ts:50-53 (every request is bounded, the child is killed); hello.ts:82-87 (the marker goes with the folder, the folder map is never written). Suspicions: hello.ts:197-201, rmSync is best effort, so on Windows the marker can survive. A kill reaches only the direct child (an npx or cmd.exe wrapper can leave an orphan; already flagged in the review). Tests: enterprise-hello.test.ts (kill checks), enterprise-hello-real-mcp.test.ts.
6. **Init args (S)**: args.ts:33-65 and 86-96. The claim at 36-37 is that a flag without its value is an error. Suspicion: line 39 accepts `''`, and line 67 then falls back to PLUR_SERVER (the same failure review finding 1 fixed for a trailing flag). Tests: enterprise-args.test.ts.
7. **URL rule vs the served installer (S)**: args.ts:14 and 86-96, against enterprise `src/install/served-installer.ts:23-27` and 51-73 (origin/agent/efi-a13). The two rules differ. The server allows plain http to 127.0.0.0/8, and the CLI allows only 127.0.0.1. The server accepts and bakes a base path, and the CLI keeps only the origin. The server accepts a port above 65535, which the CLI rejects as an invalid URL.
8. **Summary tool line (S)**: summary.ts:111-131. The plan's claim is that "every ✓ stands for a check that ran and passed". Suspicion: line 118 prints "wired — restart" on `proven` alone, without checking the hello save or this tool's recall in the same result.
9. **launch-check (S)**: launch-check.ts:20-27 and 33-69. The npx detection was already hardened in the review. Not modelled: it is a pure classifier, already tested in enterprise-launch-check.test.ts.
