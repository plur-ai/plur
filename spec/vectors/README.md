# Conformance vectors

Golden packs and `.plur` capsules with known expected outcomes, for checking that
an implementation of [the Engram Standard](../ENGRAM-STANDARD-v1.md) agrees with
everybody else's.

`../README.md` names these as the cheapest thing that unlocks the standard, and
there are now three implementations to keep honest:

| Implementation | Language | Reads |
|---|---|---|
| `@plur-ai/core` | TypeScript | the reference |
| [`plur-ai/encode`](https://github.com/plur-ai/encode) | Python | **the document**, deliberately not our code ([encode#32](https://github.com/plur-ai/encode/issues/32)) |
| [`plur-ai/enterprise`](https://github.com/plur-ai/enterprise) | TypeScript | adopting the format for import ([enterprise#1050](https://github.com/plur-ai/enterprise/issues/1050)) |

Encode is why these exist. It builds a producer from §5 without reading the
reference implementation, so anything ambiguous surfaces there as a silent
disagreement. These vectors turn it back into a loud one.

## The rule that makes them worth having

**Python authors them. TypeScript verifies them.**

A vector generated by the reference and then checked by the reference proves only
that the code agrees with itself. The expected `INTEGRITY` values here come from
`hashlib` and a hand-written serializer that share no code with `packs.ts`, so a
disagreement is a real interoperability failure rather than a broken test.

The bytes are **committed**, not generated at test time. `build.py` exists to
record how they were made and to rebuild them when a rule changes deliberately —
never as a step in the test run.

## Layout

```
vectors/
├── build.py            builds the pack vectors        (Python, stdlib only)
├── build_capsules.py   builds the capsule fixtures    (Python, stdlib only)
├── verify.py           checks packs from outside      (Python, stdlib only)
├── index.json          the packs and what to expect
├── capsules.json       the capsules and what to expect
├── packs/              11 pack directories
└── capsules/           10 .plur files
```

The TypeScript side is `packages/core/test/spec-vectors.test.ts`, which runs in
the ordinary suite.

## Running them

```bash
# From outside the reference, no Node required — what a third party runs
python3 verify.py --index index.json

# The reference's side
pnpm vitest run packages/core/test/spec-vectors.test.ts

# Did anybody edit a vector by hand?
python3 build.py --check
```

`verify.py` needs **no dependencies at all** — that is deliberate, so a producer
can run it anywhere, including in a container that has no package index.

## The vectors

### Packs

| Vector | Expect | What it pins down |
|---|---|---|
| `minimal` | load | `INTEGRITY` is OPTIONAL on disk (§5.1) |
| `with-integrity` | load | the ordinary case: recomputing over raw bytes reproduces the shipped value |
| `with-provenance` | load | `provenance/` is OPTIONAL and **not covered by the hash** — adding records must not move it |
| `non-latin` | load | §5.5 hashes raw bytes; the only vector that catches an encoding assumption |
| `unknown-root-field` | load | §10.3: unknown manifest fields at root MUST survive |
| `unknown-metadata-field` | **disputed** | see below |
| `integrity-mismatch` | reject | §5.5: a mismatch MUST be a failed integrity check |
| `orphan-provenance-record` | load, report | profile §5.4.2: a record naming an engram not in the pack |
| `corrupt-provenance-record` | load, report | profile §5.4.2: unreadable records are counted, never silently skipped |
| `private-engram-shipped` | reject | §4.14 invariant 7: a producer cannot emit this, and a consumer must still refuse it |
| `pinned-engram-shipped` | load, neutralized | §5.4: `pinned` MUST be stripped on import and the stripping reported |

### Capsules

One valid capsule and nine rejections, one per §6.7 check: bad magic, unknown
`FormatVersion`, a set reserved flag bit, declared-size mismatch, SHA-256
mismatch, a truncated preamble, a truncated payload, `COMPRESSED` disagreeing
with the payload descriptor, and `SIGNED` with no trailer.

The negatives carry the weight. §6.7 lists checks a reader MUST perform, and a
check nobody has seen fail is not a check.

**§6 had no producer and no consumer anywhere** when these were written —
`capsule.ts` can read and write capsules and nothing calls it. So these are the
first bytes the format has been asked to agree with, and
[encode#30](https://github.com/plur-ai/encode/issues/30) would make Encode the
first real producer.

## `unknown-metadata-field` asserts nothing, on purpose

It holds a contradiction open rather than picking a winner.

§10.3 says unknown manifest fields MUST be preserved. The published
`pack-manifest.schema.json` sets `additionalProperties: false` on `metadata`, and
`PackManifestSchema` has no `.passthrough()`. The two disagree, and
[#1029](https://github.com/plur-ai/plur/issues/1029) has not decided which gives
way.

Asserting either behaviour here would settle it by accident. What the vector does
assert is that its hash agrees across implementations either way — and that the
question cannot be quietly forgotten, because a file in this directory is asking
it.

## When a vector fails

**Establish which side is wrong before changing anything.** These caught a real
mistake within an hour of existing: the first `valid-minimal` capsule omitted
`manifest_summary.engram_count`, the reference rejected it, and the reference was
right — §6.4 marks the field REQUIRED. The fixture was fixed, not the reader.

Do not edit a vector to make a test pass. If the code changed deliberately,
rebuild with `build.py` and say so in the commit; the diff in the committed bytes
is the record that a wire format moved.
